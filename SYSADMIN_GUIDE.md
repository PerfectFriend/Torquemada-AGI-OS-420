# W420 Install — Руководство системного администратора

## Установка

### Требования
- Linux (x86_64)
- Rust toolchain (через ~/build/env.sh)
- OpenSSH Client (для админки хостов)
- fpm / rpmbuild (для сборки .deb/.rpm пакетов)

### Установка зависимостей

```bash
# Debian/Ubuntu
sudo apt-get install -y openssh-client dpkg

# RHEL/CentOS/Fedora
sudo dnf install -y openssh-clients rpm

# Arch
sudo pacman -S openssh
```

### Сборка из исходников

```bash
source ~/build/env.sh
cd /home/thomas/w420-install
cargo build --release
```

Бинарный файл будет в `target/release/w420`.

## Первоначальная настройка

При первом запуске приложение создаёт директорию `~/.w420/` со следующими файлами:

| Файл | Назначение |
|------|------------|
| `~/.w420/hosts.db` | База данных админки хостов |
| `~/.w420/threats.db` | База данных киберугроз |
| `~/.w420/ai_providers.db` | База данных AI-провайдеров и ключей |
| `~/.w420/ai_encryption_salt` | Соль для шифрования API-ключей |
| `~/.w420/security_ai.json` | Конфигурация AI-движка безопасности |

## Админка хостов (DameWare-like)

### Добавление хоста

Через интерфейс или API команда `hosts_add`:

Параметры:
- `name` — отображаемое имя хоста
- `ip` — IP-адрес или hostname
- `port` — SSH порт (по умолчанию 22)
- `username` — имя пользователя (по умолчанию root)
- `os_type` — тип ОС: linux, windows, macos
- `auth_method` — метод аутентификации: password, key, none
- `credential` — пароль или путь к ключу (зашифруется автоматически)

### Проверка статуса хостов

Команда `hosts_status_all` проверяет все хосты (TCP подключение к SSH порту) и возвращает статус online/offline с измерением latency.

### Выполнение команд на хостах

Команда `hosts_exec` выполняет произвольную команду на выбранном хосте через SSH. Результат включает stdout, stderr и код возврата.

## Мониторинг киберугроз

### Сканирование системы

Команда `threats_scan` сканирует установленные пакеты (через dpkg-query, rpm, apk или brew) и сопоставняет их с базой известных уязвимостей CVE.

### Просмотр уязвимостей

Команда `threats_list` возвращает список всех известных уязвимостей с возможностью фильтрации по уровню серьезности (critical, high, medium, low).

### Алерты

Критические и высокоуровневые уязвимости автоматически создают алерты. Команда `threats_alerts` возвращает список алертов. Команда `threats_acknowledge_alert` помечает алерт как подтверждённый.

### Источники угроз

По умолчанию подключены источники:
- NVD (National Vulnerability Database)
- GitHub Security Advisories

Команда `threats_sync` синхронизирует уязвимости из внешних источников.

## AI-движок безопасности

### Включение AI-движка

Команда `security_ai_set_config` с параметром `enabled: true`.

### Настройка провайдера

В конфигурации указывается провайдер AI по умолчанию (например, Ollama для локальной работы, OpenAI для облачной).

Провайдеры и их ключи настраиваются через модуль w420-ai (база `~/.w420/ai_providers.db`).

### AI-анализ уязвимости

Команда `security_ai_analyze` принимает описание уязвимости и возвращает AI-анализ с уровнем риска, рекомендациями и оценками приоритета.

### Автоматический ответ на угрозу

Команда `security_ai_auto_response` генерирует автоматический ответ на основе серьезности угрозы:
- critical → block (блокировка, требует подтверждения)
- high → patch (применение патча)
- medium → monitor (мониторинг)
- low → ignore (игнорирование)

### Отчёт о безопасности

Команда `security_ai_report` генерирует полный отчёт о состоянии безопасности системы с рекомендациями AI.

## Конфигурация AI-движка

Файл `~/.w420/security_ai.json`:

```json
{
  "enabled": false,
  "default_provider": "Ollama",
  "auto_response_threshold": "high",
  "require_approval_for_critical": true,
  "auto_patch_enabled": false
}
```

Параметры:
- `enabled` — включить/выключить AI-движок
- `default_provider` — провайдер AI по умолчанию
- `auto_response_threshold` — порог для автоматического реагирования (high, medium, low)
- `require_approval_for_critical` — требовать подтверждения для критических действий
- `auto_patch_enabled` — включить автоматическое исправление уязвимостей

## Безопасность

### Шифрование

Все конфиденциальные данные (API-ключи, пароли хостов) шифруются AES-256-GCM с ключом,derived через PBKDF2. Соль хранится в `~/.w420/ai_encryption_salt`.

### SSH

Для подключения к хостам используется системный SSH клиент. Рекомендуется использовать аутентификацию по ключам вместо паролей.

### Сетевая изоляция

- TTS сервер доступен только на 127.0.0.1 с токеном X-W420-Token
- sing-box mixed-inbound только на 127.0.0.1
- Все внешние подключения через sing-box sidecar

## Устранение неполадок

| Проблема | Решение |
|----------|---------|
| Хост не отображается как online | Проверьте SSH порт и доступность хоста |
| AI-анализ не работает | Проверьте, что провайдер настроен в w420-ai и ключ API добавлен |
| Уязвимости не находятся | Убедитесь, что установлен менеджер пакетов (dpkg, rpm, apk) |
| Ошибка шифрования ключей | Проверьте `~/.w420/ai_encryption_salt` |

## Поддерживаемые ОС

- Debian/Ubuntu (dpkg-query для сканирования пакетов)
- RHEL/CentOS/Fedora (rpm для сканирования пакетов)
- Alpine Linux (apk для сканирования пакетов)
- macOS (brew для сканирования пакетов)

## Структура кода

Все модули находятся в `app/src-tauri/src/`:
- `hosts.rs` — админка хостов
- `threats.rs` — мониторинг киберугроз
- `security_ai.rs` — AI-движок безопасности
- `bridge.rs` — управление конфигурацией и мостом
- `sysops.rs` — системные операции (сканирование, FIM)
- `tor.rs` — управление Tor
- `lib.rs` — точка входа, регистрация модулей и команд

Код прокомментирован на русском языке для облегчения дальнейшей разработки и эволюции проекта.
